# datakit 通用规范

> **文档性质**：执行标准（Normative Specification）
> **适用范围**：`datakit` 通用数据处理 SDK
> **读者对象**：使用本 SDK 做「采集 → 描述 → 清洗 → 校验 → 映射」的数据工程师 / 分析人员
> **契约版本**：`v0.1`
> **配套文档**：`README.md`（快速上手）、`DEVELOPMENT_GUIDE.md`（扩展开发指引）

本文定义 **所有数据流程** 都必须遵守的通用规范。不同数据集（FDIC 网点、深圳共享单车、
SNAP 签到图等）共用同一套流程骨架，差异仅在「字段角色、清洗计划、映射方案、断言口径」
这些**目的相关**的注入口径上，而不在流程本身。

---

## 1. 设计原则（强制）

| 原则 | 说明 |
| --- | --- |
| **源数据只读** | SDK 对输入文件只做只读探测/读取，绝不写回源文件；一切产出落到调用方指定的输出目录 |
| **每步有报告与日志** | 五个阶段各自产出可机读（JSON）与可人读（Markdown）报告，清洗/决策动作落日志 |
| **目的驱动** | 异常值、空值的「是否异常」取决于分析目的，通过字段角色与清洗计划显式表达，不搞一刀切 |
| **可追溯** | 数据集携带来源/格式/指纹元信息；清洗动作记录「列/行/原值/新值/原因/是否可逆」 |
| **纯函数式数据流转** | `clean` / `map` 返回新 `Dataset`，不原地修改输入 |

---

## 2. 流程总览

```
数据目录（只读源）
   │ ① 采集 discover.scan
   ▼
Catalog（文件清单 + 指纹 + 数据集分组）
   │ ② 描述性统计 profile
   ▼
Profile（字段画像 + 异常值 + 空值）
   │ ③ 清洗 clean
   ▼
CleanResult（清洗数据 + 决策日志）
   │ ④ 校验分析 validate / compare
   ▼
ValidationReport / ComparisonReport（断言 + 前后对比 + 建议）
   │ ⑤ 映射 map
   ▼
MapResult（映射数据 + 映射报告）
```

`datakit.Workflow` 把上述五步串成一条可复现的流水线，自动在输出目录生成
`01_discover/`、`02_profile/`、`03_clean/`、`04_validate/`、`05_map/` 与 `pipeline.log`。

## 3. 数据格式与 IO 契约

### 3.1 支持格式

| 格式 | 扩展名 | 规范化结果 |
| --- | --- | --- |
| CSV | `.csv` | `DataFrame`（自动尝试 utf-8-sig / utf-8 / gb18030 / latin-1） |
| TSV | `.tsv` | `DataFrame`（tab 分隔） |
| JSON | `.json` | `DataFrame`（数组） |
| JSONL / NDJSON | `.jsonl` `.ndjson` | `DataFrame`（换行分隔） |
| XML | `.xml` | 重复子元素 → 记录；属性/嵌套递归扁平化为列 |
| RDF | `.rdf` `.ttl` `.nt` `.n3` | `DataFrame(subject, predicate, object)` |
| XLSX | `.xlsx` | `DataFrame`（第一个 sheet） |
| 压缩 | `*.gz` | 文本类文件的 gzip 包裹 |

### 3.2 契约

- 读取统一入口 `dk.read(path)` 按扩展名自动分派；`dk.detect_format` 负责格式识别。
- RDF 依赖 `rdflib`（可选 extra），H3 依赖 `h3`（可选 extra）；缺失时抛**带安装指引**的错误。
- 写入入口 `dk.write(dataset, path)`；RDF / XML 当前只读不写。
- 所有读写用 UTF-8；中文不做转义（`ensure_ascii=False`）。

## 4. 核心抽象

### 4.1 `Dataset`

统一数据容器：包装 `pandas.DataFrame` 并携带 `DatasetMeta`（来源/格式/行数/列数/MD5）。
`with_frame()` 基于新 DataFrame 继承元信息，保证清洗/映射后来源可追溯。

### 4.2 `Role`（字段角色）

| 角色 | 值 | 空值语义 | 异常值/清洗取向 |
| --- | --- | --- | --- |
| `KEY` | `key` | 缺陷：主键缺失通常剔除 | 缺失即阻断 |
| `EVENT` | `event` | 信息：缺失常表示右删失/未发生 | 不当作脏数据 |
| `TIME_VARYING` | `time_varying` | 可选：可标记/填充 | 缺失不轻易删行 |
| `SPATIAL` | `spatial` | 需处理：影响映射 | 边界/精度检查 |
| `CATEGORICAL` | `categorical` | 可重编码为 UNKNOWN | 缺失归入 UNKNOWN 类 |
| `NUMERIC` | `numeric` | 可选：可标记/填充 | 统计量 + 离群检测 |
| `TARGET` | `target` | 仅观测，不自动清洗 | 只观测 |
| `IGNORE` | `ignore` | 忽略 | 不参与统计/清洗 |

角色由 `infer_roles` 提供启发式默认，**用户应结合目的显式覆盖**。

### 4.3 `Profile`

描述性统计产物：`fields`（逐字段画像）、`outliers`（异常值表）、`nulls`（空值表）、`summary`。
支持三种离群检测方法：`iqr` / `zscore` / `mad`（阈值可配）。

## 5. 阶段规范

### 5.1 ① 采集（`discover`）

- 递归扫描目录，识别数据文件（默认忽略 `_*`、`.*`、日志）。
- 每个文件产指纹：大小、列名（表头只读探测）、可选 MD5 / 行数。
- 按「目录 + 文件名模式」分组：连续数字归一为 `#`，如 `fdic_sod_1994.csv` → 组 `fdic_sod_#`。
- 产物 `Catalog`：`to_report()`（JSON）、`to_markdown()`（人读清单）、`to_frame()`。

### 5.2 ② 描述性统计（`profile`）

- 逐字段：非空计数、缺失率、唯一值、数据类型。
- 数值列：min/max/mean/median/std、分位数、负值率、零值率。
- 类别列：取值分布 Top-N；时间列：范围。
- 异常值表：`field / index / value / method / lower_bound / upper_bound`。
- 空值表：`field / null_count / null_rate / role / semantic`（语义随角色变化）。

### 5.3 ③ 清洗（`clean`）

- 由一组 `CleanAction` 顺序执行，支持：
  `drop_na`、`fill`、`clip`、`replace`、`drop_duplicates`、`astype`、`winsorize`、
  `drop_columns`、`filter`。
- 每个动作写 `DecisionLog`：步骤、动作、字段、影响行数、原值/新值概况、原因、是否可逆；
  删行额外记录被删索引（审计用）。
- `CleanPlan.from_spec` 支持把清洗口径外置为配置。

### 5.4 ④ 校验分析（`validate` / `compare`）

- `validate` 执行断言（唯一性/空值率/非负/范围/允许值/重复/行数列数），产出通过/失败报告。
- `compare` 对比清洗前后 `Profile`，逐字段给缺失率/异常值变化，并输出**建议**：
  - 关键字段清洗后仍缺失，或剔除行占比超阈值 → 「还原并更温和地重洗」；
  - 否则 → 「可进入映射阶段」。
- 建议仅作人工参考，不替代人工决策。

### 5.5 ⑤ 映射（`map`）

- `MappingScheme` 固化一种映射口径：`rename`、`derive`、`bin`、`onehot`、`code`、
  `aggregate`、`geocode`（H3）、`drop`。
- 产物 `MapResult`：映射后 `Dataset` + 操作明细报告。
- 「不同想法 → 不同映射方案」：方案是参数，流程与数据无关。

## 6. 报告与日志契约

| 载体 | 内容 | 写出接口 |
| --- | --- | --- |
| JSON 报告 | 机器可读结构化结果 | `write_report` / `write_json` |
| Markdown 报告 | 人读清单/对比表 | `write_report`（`to_markdown`）/ `write_markdown` |
| JSONL | 逐条记录（如问题清单） | `write_jsonl` |
| 决策日志 | 清洗动作留痕 | `DecisionLog.to_markdown()` |
| 流水线日志 | 阶段摘要 + 时间戳 | `Workflow`（`pipeline.log`） |

所有报告对象统一实现 `to_report()`（→ dict）与 `to_markdown()`（→ str）。

---

## 7. 错误与异常

| 异常 | 场景 |
| --- | --- |
| `DataKitError` | SDK 通用基类 |
| `FormatNotSupportedError` | 格式不支持 |
| `ImportError`（带指引） | 可选依赖缺失（rdflib / h3） |
| `ValueError` | 参数非法（未知方法/op/check） |

约定：**可诊断的失败抛明确异常，不静默吞错**；IO 探测类操作（如列名只读探测）在失败时
降级为 `None` 而非中断整个扫描。

## 8. 命名规范

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| 包名 | 小写、下划线 | `datakit` |
| 模块 | 动/名词，小写 | `discover` `profile` `clean` `validate` `map` |
| 数据集分组 | 连续数字 → `#` | `fdic_sod_#`、`bike_#_p#` |
| 字段角色 | 枚举值小写 | `key` / `event` / `spatial` |
| 报告文件名 | 阶段语义 | `catalog` `profile` `decisions` `comparison` `map` |

---

## 9. 安全与边界

- 禁止修改源数据、系统环境、工作空间外文件。
- 不直连数据库、不调用外部服务；SDK 只做本地文件读写与内存计算。
- 大目录扫描默认**不**计算 MD5 / 行数（成本高），按需开启 `with_md5` / `count_rows`。
