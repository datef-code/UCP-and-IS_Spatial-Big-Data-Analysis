## 一、必修缺陷（按优先级）

### P0-1 · 边际效应的标准误取错字段（数值错误）

**位置**
```183:183:portal/assets/engines.js
    const b1 = tw.post_x_strength, b1se = tw.post_x_strength;
```
**事实**：数据层已有正确字段
```421:421:portal/data/portal_data.json
      "post_x_strength_se": 0.00171193124972214,
```
但引擎用系数 `0.013823` 当 SE。

**影响（已复算）**：默认强度 `s=1.61`
- 正确：`SE = √(0.001643² + 1.61²·0.001712²) = 0.00321` → Δ=−3.03pp，95% CI≈[−3.66pp, −2.41pp]，**显著**
- 现状：`SE = √(0.001643² + 1.61²·0.013823²) = 0.02232` → 95% CI≈[−7.41pp, +1.34pp]，**跨 0**

即页面会告诉用户"效应与 0 无法区分"，与结论叙事直接冲突。同一个错值还被 `app.js:874` 独立重算了一遍，强度曲线的置信带同样错。

**动作**
1. `engines.js:183` → `const b1se = tw.post_x_strength_se;`
2. `app.js:874` 改用引擎返回值（不要再在视图层重算 SE），或同样改字段。
3. 顺带修正 `engines.js:198` 的注释：忽略协方差**未必保守**（β_post 与交互项通常负相关，忽略可能使区间偏窄），改为"近似忽略协方差，方向未定"。
4. **补单测**（这是 bug 逃逸的根本原因）：
   ```js
   // 断言边际效应 SE 与数据层一致
   const r = E.impact({ strength: 1.61 }, D);
   const exp = Math.sqrt(D.impact.twfe.post_se**2 + 1.61**2 * D.impact.twfe.post_x_strength_se**2);
   assert.ok(Math.abs(r.marginal.atInput.se - exp) < 1e-12);
   ```
5. （更强）在 `build_data.py` 里顺带产出 `expected_engine_outputs.json`（若干输入 → 期望 η/SE/CI），单测直接对拍，今后数据层刷新可自动发现口径漂移。

### P1-1 · 同一项目出现两个"结论强度"等级

**位置**
- 工作台/报告：`app.js` `computeGrade()`（`app.js:94-112`），报告取 `app.js:571`。
- 冲击页徽章：`app.js:902` 渲染的是 `impact()` 内部自算的 grade；而该 grade 在
  ```261:265:portal/assets/engines.js
        grade: gradeEvidence({
          exogenous: null, preTrendMaxAbsT: es.pre_trend_max_abs_t,
  ```
  把 `exogenous` 写死为 `null`。

**复现**：问卷选"外生冲击"，`preTrendMaxAbsT=4.12`、量级比≈0.157。
`computeGrade` → 外生(A) → 前趋势显著(B) → 比值<0.5 → **B**；
`impact().grade` → 外生未判定(B) → 前趋势显著(C) → **C**。
工作台/报告写 B，冲击页写 C。

**动作**（选一，建议 1）
1. 让 `paint()` 统一用 `computeGrade(p)`（把 intake 答案传进去），`impact()` 只负责数值、不负责评级；
2. 或把 `intakeAnswers` 传入 `impact(input, D, { exogenous })`。
3. 补单测：给定同一 intake 答案，"工作台等级 === 冲击页等级 === 报告等级"。

### P1-2 · 示例项目的外生性字段类型与问卷不一致

**位置**：`data/tools.js`
```26:26:portal/data/tools.js
            years: 10, eventDefined: true, exogenous: true,
```
```43:43:portal/data/tools.js
            years: 4, eventDefined: true, exogenous: false,
```
问卷 `enum3` 的取值是 `'yes' | 'no' | 'unsure'`；而三处转换都按字符串判定：
`app.js:97`（computeGrade）、`app.js:556`（报告）、`app.js:824`（paint）。

**后果**：载入示例后 ① 分段按钮不高亮；② `true` 被判为 `null` → 准入等级默认降 B 并弹出"处理事件为内生决策"缺口。**示例即首屏演示，直接暴露。**

**动作**
1. 把示例改为 `exogenous: 'yes'` / `'no'`；
2. 顺手做类型兼容（`true→'yes'`、`false→'no'`），避免导入旧项目 JSON 再次踩坑；
3. 补单测：载入每个示例后，`intake().ceiling` 与示例描述一致（A 示例应得 B，B 示例应得 C）。

## 三、产品与工程优化建议（非缺陷，按投入产出排序）

**A. 让"结果"可被复核（补齐产品闭环，投入小、收益大）**
- 报告加「报告指纹」：对（输入 + 所用系数 + `meta.generated_at`）算 SHA-256（`crypto.subtle`，`file://` 可用）。当前报告只能说"数据层生成于某时"，无法回答"这份 PDF 对应哪一版数据层"。
- `meta` 加 `schema_version` + 必需 key 清单；`engines.js` 启动自检，缺 key 时整体降级为"数据层不兼容"，而不是散落 `null`。

**B. 把"审查发现"变成可追踪工程项**
- `tools.js` 的 `patches` 目前是静态文案。可加 `status/owner/updated_at` 并由 `build_data.py` 从 `technical_report.md` 等产物核对状态，避免"看板说待修、实际已修"。

**C. 测试补到"产品级"**
单测现有 26 项缺的正是最容易逃逸的地方：
1. 边际效应 SE / CI 对拍（见 P0-1）；
2. 三处等级一致性（见 P1-1）；
3. 示例项目 → 期望等级（见 P1-2）；
4. `intake` 的 `unsure`/`null` 分支措辞；
5. `buildReport`：某模块缺失时对应章节应消失（现有仅覆盖"全空项目"）；
6. `serve.py` 的 `detect_columns`（中英文列名、`x/y` 误命中）与 `health_check`（缺失集中度、坐标阈值）。
建议把 1/3/4 做成"黄金数值回归"，由 `build_data.py` 生成期望值文件，单测对拍。

**D. 本地服务的定位**
`serve.py` 体检规则只覆盖了 project1 的三类坑（主键/坐标/年份）。可把 project2（目标泄漏：全期聚合特征 join 回逐年）与 project6（换权重/换尺度导致 Moran's I 翻转）也做成体检项——这是"引擎"相对"报告"的真实增量。

**E. 文档收尾**
`DESIGN.md §六` 写"模块 2/3 需先修 P0 才能上线"，而 v2 实际已带披露上线。二者择一：
- 若坚持"披露即上线"，把 `DESIGN.md §六` 的"条件上线"改为"带披露上线 + 强制边界"；
- 否则应把模块 2/3 置为"开发中"。
现状是设计与实现口径不一致，外部评审会抓。
