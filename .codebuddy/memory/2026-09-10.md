## project1_fdic_spatial · 商业化与外部适用性分析
- 新增 `project1_fdic_spatial/产品商业化与外部适用性分析_20260910.md`（V1.0）。
- 核心论点（后续讨论以此为准）：
  1. 「结论」卖不出价（数据免费公开、可复现），可卖的是「空间影响评估引擎 + 工程规范 + 踩坑清单」；
  2. 最可行市场不是银行，而是有连锁门店且会关店的零售/餐饮/药店/加油站/充电桩；首单宜走 B 类咨询项目制（M1）；
  3. 商业模式三级跳：项目制咨询 → 标准化评估报告 → 门店暴露度指标订阅（M3 才是规模化形态，M4 SaaS 暂缓）；
  4. 迁移难度排序：展示层/工程层/空间层 ≈ 1–2 周可复用；识别层 2–4 周（新场景内生性更强）；数据层 3–6 周最难（主键稳定性/坐标精度/缺失随机性必重踩）；
  5. 数据可得性分级 A–D：FDIC SOD 属稀有 A 级（长周期+网点级+结果变量+免费可商用）；国内可拿位置与存续但**无网点级存款** → 服务国内客户须依赖客户自有经营数据。

## project1_fdic_spatial · 修复 Kepler.gl 页面 "KeplerGL undefined"
- 改动：`09_interactive/09_interactive.py`（模板与生成逻辑）、`09_interactive/README.md`、
  重新生成 `09_interactive/output/{kepler_timeline.html, index.html, kepler_timeline_config.json, kepler_timeline_events.csv}`。
- **Kepler.gl 3.x UMD 五条硬知识**（以后别再踩，已写入 09 README「依赖与离线」）：
  1. UMD 全局名是 **`KeplerGl`**，不是 `KeplerGL` → 旧判断恒为真，页面必报错（真正根因）；
  2. UMD 把 react / react-dom / redux / react-redux / styled-components 列为 **externals**，必须先挂这 5 个全局；
  3. 3.x 的 `default` 导出是 **React.memo 对象，不能 new** → 用官方「createStore + Provider + `KeplerGl.KeplerGl`」；
  4. UMD **没有 `app.csvDataset()`** → 用 `KeplerGl.processCsvData()` + `store.dispatch(KeplerGl.addDataToMap(...))`；
  5. **未挂载就 dispatch 会被静默丢弃**（datasets=0 且无报错）→ 必须等 `[class*=kepler-gl]` 出现再灌数据。
- 版本锁定原因：React ≥19 / redux 5 / react-redux 9 **不再提供 UMD** → 锁 react 18.3.1、redux 4.2.1、react-redux 8.1.3、styled-components 6.1.8、kepler.gl 3.2.0。
- 依赖加载：CDN 顺序 unpkg → jsdelivr → npmmirror；`?local=1` 或离线时优先读 `assets/kepler/`；全部失败则降级提示并指向 `spacetime.html`（mp4 离线可看）。无 Mapbox token 时底图空白但 deck.gl 图层正常；`?mapbox=` 可注入 token。
- 验证方式（可复用）：无头 Edge `--dump-dom` 受虚拟时钟影响不可靠；改用 **playwright + `channel="msedge"` 真实等待**（60–100 s）才可信。实测最终态：面板隐藏、`Datasets(2)`（22,406 + 51,251 行）、Hexagon/Point 图层、canvas 3、时间轴控件 12。
- 注意：`07_visualize/output/kepler/kepler_map.html` 仍是**同一套旧写法**（同样 bug），未改（超出本次范围）。
- 07 的 `closed_events.csv` / `h3_cells.csv` 已不在 output 目录，本次是从旧 HTML 的 base64 还原后重生成。
